Module 1 — Attacker already has system access

Practice investigating and recovering from changes made by an attacker who already has system access.

Task 1.1 — Service tampering and recovery

Roles and command windows: each team runs only its assigned steps in its own terminal or PowerShell window. Attacker commands do not inherit defender variables. Run each role’s setup commands in that role’s window; keep it open for that role’s later steps. Defender baselines and recovery files remain with the defender. Scenario preparation changes the lab state, but does not require the attacker to run defender commands. For Module 2, attacker actions run outside the target VM; Task 2.2 login attempts are instructor-operated.

Practice investigating and recovering from service outages caused by an attacker who already has administrative access. Practice web and DNS service outages using the steps below:

Before you begin

Run service and investigation commands in elevated PowerShell inside the assigned Windows VM. Perform the labeled laptop checks on your own computer. Keep Remote Desktop, networking and the firewall available throughout the exercise.

Round order: the defender completes Defender step 1 before the attack. Then follow the handoffs below. Each role uses its own command window and numbered steps.

Attacker

Step 1 — Stop IIS

Record the time, execute the stop once and hand over to the defender.

Laptop browser check — outage

Location: your own computer, outside the VM. With the HTTP service stopped, test again from your own campus laptop before the defender restores it. Open http://128.198.74.133:28080/index.html. Hard-refresh to avoid a cached page, or use the command below for a new request. Keep this separate from the guest-side commands above.

macOS/Linux laptop, Terminal:

Expect a request failure, empty reply, timeout or HTTP error; the operational page must not be returned. IIS can return an HTTP error while its HTTP.sys TCP listener remains available. This is an HTTP service exercise; do not stop networking, RDP or TCP itself.

Task 1.2 — Web-content tampering and evidence

Investigate unauthorized changes to a webpage even when the web service still responds. Use the role-specific steps below.

Use your assigned trainee account in elevated PowerShell inside the Windows VM. The attacker and defender use separate PowerShell windows. The defender keeps their window open for the defender preparation, investigation and recovery steps; the attacker starts at Attacker step 1 in their own window. When you switch roles, repeat Defender step 1 to create a new directory; previous files remain saved.

Round order: the defender completes Defender step 1 before the attack. Then follow the handoffs below. Each role uses its own command window and numbered steps.

Attacker

Step 1 — Change the page

Record the time of the assigned change:

(Get-Date).ToUniversalTime().ToString('o')

Open your own Administrator PowerShell window inside the Windows VM. You do not need to run Defender step 1 or use the defender’s variables or backup directory. Run the entire block below to set the path, check that the file exists, and replace only the exercise webpage with the changed-page marker:

Administrator PowerShell required — inside the Windows VM. How to open it

$site = 'C:\inetpub\wwwroot\index.html'
if (Test-Path -LiteralPath $site -PathType Leaf) {
    Set-Content -LiteralPath $site -Value 'CCDC exercise: changed page' -Encoding UTF8 -ErrorAction Stop
} else {
    throw "Exercise webpage not found: $site. Check the path before continuing."
}

Troubleshooting: “Cannot bind argument to parameter 'LiteralPath' because it is null” means $site has no value in the current PowerShell session. Variables set in another window, including a window opened before elevation, do not carry over. Run the whole block, including the first line.

Check that IIS remains running and request the changed page:

Get-Service W3SVC
(Invoke-WebRequest http://172.29.242.40/index.html -UseBasicParsing -TimeoutSec 5).Content

Expect a successful response containing CCDC exercise: changed page. Keep IIS, DNS and remote desktop running. Do not modify the recovery copy or baseline checksum. Hand over to the defender.

Defender

Step 1 — Prepare a trusted recovery copy

Before the attack: complete this preparation, then tell the other team the lab is ready. Resume the remaining defender steps after the assigned action.

Check IIS and DNS, then request the operational page:

Get-Service W3SVC,DNS
(Invoke-WebRequest http://172.29.242.40/index.html -UseBasicParsing -TimeoutSec 5).Content

Both services should be running and the page should show CCDC Windows intranet: operational. Confirm the same content from your campus laptop at the Windows website. If the previous round left the page changed, restore that round’s original using Defender step 3 before making another recovery copy.

Set the webpage path and create a unique name for this round’s exercise directory:

$site = 'C:\inetpub\wwwroot\index.html'
$case = Join-Path $HOME ('CCDC-Exercise-1-2-' + [guid]::NewGuid().ToString('N'))

Check that the webpage exists; expect True. Stop here if the path is incorrect:

Test-Path -LiteralPath $site

Create the exercise directory. Continue only if it is created successfully:

New-Item -ItemType Directory -Path $case -ErrorAction Stop

Save a trusted copy of the operational page before the attack:

Administrator PowerShell required — inside the Windows VM. How to open it

Copy-Item -LiteralPath $site -Destination "$case\original.html" -ErrorAction Stop

Save its SHA-256 checksum in a separate baseline file:

(Get-FileHash -LiteralPath $site -Algorithm SHA256).Hash | Set-Content -LiteralPath "$case\original.sha256" -Encoding ASCII

Display and record the exercise-directory path:

$case

Official command documentation: Join-Path · Test-Path · New-Item · Copy-Item · Get-FileHash · Set-Content

Keep original.html and original.sha256 unchanged. If you reopen PowerShell during the round, set $site to the webpage path and $case to this round’s recorded directory before continuing.

Note: in a real environment, store the trusted recovery copy and baseline checksum outside the victim computer so an attacker who compromises that computer cannot alter them.

Step 2 — Investigate before restoring

From your campus laptop, make a fresh request to the Windows website. It may return HTTP 200 while showing the wrong content. Return to the defender’s Administrator PowerShell window from Defender step 1 to inspect and preserve evidence before recovery. If that window was closed, set $site to C:\inetpub\wwwroot\index.html and $case to the recorded Defender step 1 directory. Do not create a new baseline from the changed page.

Inspect the changed file’s metadata and access permissions:

Get-Item -LiteralPath $site | Select-Object FullName,Length,LastWriteTimeUtc
Get-Acl -LiteralPath $site | Format-List

Preserve the changed page in this round’s directory:

Administrator PowerShell required — inside the Windows VM. How to open it

Copy-Item -LiteralPath $site -Destination "$case\changed.html" -ErrorAction Stop

Display the changed content and its checksum:

Get-Content -LiteralPath $site
Get-FileHash -LiteralPath $site -Algorithm SHA256

Compare the current checksum with the saved baseline. Expect False after the attack:

(Get-FileHash -LiteralPath $site -Algorithm SHA256).Hash -eq (Get-Content -LiteralPath "$case\original.sha256").Trim()

Official command documentation: Get-Item · Get-Acl · Get-Content

Save the output or screenshots. Review IIS access records at the configured logging location (normally C:\inetpub\logs\LogFiles\W3SVC1). Access logs show requests, not who edited the file. File-change attribution requires auditing enabled before the change; timestamps alone do not establish an attacker’s identity.

Step 3 — Recover and verify

Restore your trusted original. Continue only if the copy succeeds:

Administrator PowerShell required — inside the Windows VM. How to open it

Copy-Item -LiteralPath "$case\original.html" -Destination $site -Force -ErrorAction Stop

Compare the restored file with the saved baseline checksum; expect True:

(Get-FileHash -LiteralPath $site -Algorithm SHA256).Hash -eq (Get-Content -LiteralPath "$case\original.sha256").Trim()

Check the services and restored webpage:

Get-Service W3SVC,DNS,TermService
(Invoke-WebRequest http://172.29.242.40/index.html -UseBasicParsing -TimeoutSec 5).Content

Verify that DNS still answers:

Resolve-DnsName www.training.test -Server 172.29.242.40 -DnsOnly -NoHostsFile

All three services should be running, the checksum comparison should be True and the page should show the operational intranet. Repeat the laptop HTTP check with a fresh request. Keep this round’s evidence and original files, switch roles and repeat from Defender step 1 with a new directory.

Practice check: show the changed page, preserved evidence, matching restored checksum and normal service. Explain why HTTP 200 alone did not prove the page was correct. No written report submission is required.

Task 1.3 — Firewall rule configuration and recovery

Investigate an HTTP outage caused by a firewall change while IIS remains running. Follow the preparation and attack/recovery steps below:

Round order: the defender completes Defender step 1 before the attack. Then follow the handoffs below. Each role uses its own command window and numbered steps.

Attacker

Step 1 — Block incoming HTTP traffic

Use elevated PowerShell inside your assigned Windows VM. Check the starting conditions before creating the rule.

Confirm that Windows Firewall is enabled on all profiles:

Get-NetFirewallProfile | Select-Object Name,Enabled

Check the required services and request the operational page:

Get-Service W3SVC,DNS,TermService
(Invoke-WebRequest http://172.29.242.40/index.html -UseBasicParsing -TimeoutSec 5).Content

Check for an existing exercise rule; expect no output:

Get-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Block' -ErrorAction SilentlyContinue

Continue only when the firewall profiles are enabled, services are running and the operational intranet page is available. Confirm the same page from your campus laptop at the Windows website. If the exercise rule already exists, finish Defender step 3 before starting another round.

Record the time, then run the rule-creation command once:

(Get-Date).ToUniversalTime().ToString('o')

Block only incoming HTTP on TCP port 80:

Administrator PowerShell required — inside the Windows VM. How to open it

New-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Block' -DisplayName 'CCDC-Exercise-HTTP-Block' -Direction Inbound -Action Block -Protocol TCP -LocalPort 80 -Profile Any

Official command documentation: Get-NetFirewallProfile · Get-NetFirewallRule · New-NetFirewallRule

Make a fresh laptop HTTP request; expect failure or a relay error rather than the operational page. Leave IIS and DNS running and keep your remote desktop session open. This rule does not target DNS or remote desktop ports. Hand over to the defender after demonstrating the failure.

Defender

Step 1 — Configure and test an allow rule

Before the attack: complete this preparation, then tell the other team the lab is ready. Resume the remaining defender steps after the assigned action.

Practice reading and configuring a rule before the attack round. Confirm the firewall is active, normal laptop HTTP works, and the instructor has a guest recovery console. Save the initial rule listing. Keep existing rules, default policies and SSH/RDP access unchanged.

Rule fieldValue and purpose
Direction and actionInbound allow: permit requests arriving at the VM.
Protocol and portTCP 80 on the guest, not the laptop-facing relay port.
Source address172.29.242.1, the relay address normally seen in guest logs. Confirm it using an actual laptop request.
Destination addressThe assigned VM’s internal address.

A scoped allow rule does not remove broader existing permissions. This exercise teaches rule construction and troubleshooting; it does not establish that all other sources are blocked.

Inspect the active network profile and firewall policy:

Get-NetConnectionProfile
Get-NetFirewallProfile | Select-Object Name,Enabled,DefaultInboundAction

Create a uniquely named, source-scoped allow rule. If that exercise name already exists, ask the instructor to check the previous round before proceeding.

Administrator PowerShell required — inside the Windows VM. How to open it

$allow = 'CCDC-Exercise-HTTP-Allow'
if (Get-NetFirewallRule -Name $allow -ErrorAction SilentlyContinue) { throw 'Exercise allow rule already exists.' }
New-NetFirewallRule -Name $allow -DisplayName $allow -Direction Inbound -Action Allow -Protocol TCP -LocalPort 80 -LocalAddress 172.29.242.40 -RemoteAddress 172.29.242.1 -Profile Any

Inspect the rule and its separate port and address filters:

Get-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Allow' | Format-List Name,Enabled,Direction,Action,Profile
Get-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Allow' | Get-NetFirewallPortFilter
Get-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Allow' | Get-NetFirewallAddressFilter

LocalPort identifies the guest service and RemoteAddress the source. Profile Any applies the exercise rule across profiles; a real policy should select its intended profiles. Confirm a fresh laptop request to the Windows website returns operational content. Continue with the attack below. An explicit Windows block overrides an ordinary conflicting allow; adding another allow will not fix it. Windows Firewall rules do not have administrator-assigned numeric ordering.

Step 2 — Investigate the outage

Check that the services remain running and TCP port 80 still has a listener:

Get-Service W3SVC,DNS,TermService
Get-NetTCPConnection -State Listen | Where-Object LocalPort -eq 80

Inspect the enabled firewall profiles and exact exercise rule:

Get-NetFirewallProfile | Select-Object Name,Enabled
Get-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Block' | Format-List

Inspect the rule’s protocol and destination port:

Get-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Block' | Get-NetFirewallPortFilter

Confirm DNS still answers:

Resolve-DnsName www.training.test -Server 172.29.242.40 -DnsOnly -NoHostsFile

Official command documentation: Get-NetFirewallPortFilter

Preserve the output or screenshots before recovery. Expect an enabled inbound block rule for TCP port 80 while IIS, DNS and remote desktop remain running. Compare this with the failed laptop HTTP request. A listener or successful TCP connection to the relay alone does not prove that the guest’s HTTP service is reachable.

Step 3 — Recover and verify

Remove only the exact exercise rule:

Administrator PowerShell required — inside the Windows VM. How to open it

Remove-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Block'

Official command documentation: Remove-NetFirewallRule

Check that the firewall remains enabled and the exercise rule is absent:

Get-NetFirewallProfile | Select-Object Name,Enabled
Get-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Block' -ErrorAction SilentlyContinue

Check the services and request the operational page:

Get-Service W3SVC,DNS,TermService
(Invoke-WebRequest http://172.29.242.40/index.html -UseBasicParsing -TimeoutSec 5).Content

Verify DNS after recovery:

Resolve-DnsName www.training.test -Server 172.29.242.40 -DnsOnly -NoHostsFile

Expect no exercise-rule output, enabled firewall profiles, running services and the operational intranet page. Repeat the laptop HTTP check; the operational page must return and your remote desktop session must remain connected. Do not disable the firewall or change unrelated rules.

Step 4 — Restore the original policy

After removing the attack rule and verifying recovery, remove only the allow rule created in this round:

Administrator PowerShell required — inside the Windows VM. How to open it

Remove-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Allow'
Get-NetFirewallRule -Name 'CCDC-Exercise-HTTP-Allow' -ErrorAction SilentlyContinue

Compare the final rules with the saved baseline. Recheck external HTTP and legitimate remote access; on Windows, verify DNS as well. Explain the direction, source, destination, port and precedence of the rules before reversing roles. Test with fresh requests because an existing connection may not reflect a new rule.

Reference: Windows Firewall rule precedence.

Practice check: show the external HTTP failure, running IIS, the exercise block rule and successful external recovery after removal. Explain how this differs from Task 1.1. Keep the evidence, switch roles and repeat from Attacker step 1. No written report submission is required.

Task 1.4 — Compromised account and excessive privilege

Investigate an exercise account with excessive privileges and contain its access while preserving legitimate services. Complete the four steps below yourselves, then switch roles and repeat.

Use only the dedicated ccdc-demo account for this exercise. Keep your assigned trainee account’s privileges unchanged. This task starts with access to an account; it does not involve guessing or cracking passwords.

Round order: Each role uses its own command window and numbered steps.

Attacker

Step 1 — Prepare the dedicated exercise account

The attacker performs this setup and Attacker step 2 in their own VM session, using the temporary password they set here. The defender starts at Defender step 1 in a separate command window and discovers the account independently.

Use your assigned trainee account in elevated Windows PowerShell inside the Windows VM. Verify the baseline:

Check service states and request the webpage:

Get-Service W3SVC,DNS,TermService
(Invoke-WebRequest http://172.29.242.40/index.html -UseBasicParsing -TimeoutSec 5).Content

Query DNS over UDP:

Resolve-DnsName www.training.test -Server 172.29.242.40 -DnsOnly -NoHostsFile

All three services should be running, the operational intranet page should be returned and DNS should answer. Confirm the page from your campus laptop at the Windows website.

Create the dedicated account with a temporary exercise password and deliberately grant it administrator membership. Give that password to the student acting as attacker. If the account exists, complete the previous round’s cleanup before starting a fresh round. Keep this elevated PowerShell window open for the defender steps.

Check whether the exercise account exists; expect no output before a fresh round:

Get-LocalUser -Name 'ccdc-demo' -ErrorAction SilentlyContinue

If the lookup returns an account, finish the previous round’s cleanup before continuing. Do not overwrite it.

Choose a temporary exercise password; the input is hidden:

$password = Read-Host 'Temporary exercise password' -AsSecureString

Create only the dedicated exercise account. Continue only if creation succeeds:

Administrator PowerShell required — inside the Windows VM. How to open it

New-LocalUser -Name 'ccdc-demo' -Password $password -Description 'CCDC Task 1.4 exercise account' -ErrorAction Stop

Find the built-in Administrators group and inspect its current membership:

$admins = Get-LocalGroup -SID 'S-1-5-32-544'
Get-LocalGroupMember -Group $admins.Name

Deliberately grant the dedicated account excessive administrator membership:

Administrator PowerShell required — inside the Windows VM. How to open it

Add-LocalGroupMember -Group $admins.Name -Member 'ccdc-demo' -ErrorAction Stop

Verify that the account is enabled and appears in Administrators:

Get-LocalUser -Name 'ccdc-demo'
Get-LocalGroupMember -Group $admins.Name

Official command documentation: Read-Host · New-LocalUser · Get-LocalUser · Get-LocalGroup · Add-LocalGroupMember · Get-LocalGroupMember

Step 2 — Demonstrate the excessive access

Open a separate PowerShell window inside the VM. Run the following and enter the temporary exercise password:

runas /user:.\ccdc-demo "cmd.exe /k whoami /all"

In the new command window, confirm the identity is ccdc-demo and find the Administrators group in the token output. Keep this window open for the containment demonstration. UAC may mark administrator groups as deny-only in an unelevated token, so membership does not mean every process is elevated. This round demonstrates an unnecessary administrator grant; no service stop or RDP permission change is required.

Defender

Step 1 — Investigate and contain

In your own Administrator PowerShell window, inspect the account, unexpected membership and available events. Save the output or screenshots before changing the account:

Inspect the exercise account’s state and details:
